# Company Career Sites

Curated by the operator — pre-filtered for companies known to offer remote roles, so scans do **not** filter on remote/onsite, only on role/seniority match (see `profile.md`).

Legend for **ATS** column — the underlying job board platform. Knowing this lets a scan use a stable JSON API instead of scraping fragile HTML where possible.
- **Greenhouse** — public JSON feed: `https://boards-api.greenhouse.io/v1/boards/{token}/jobs?content=true`
- **Ashby** — public JSON feed: `https://api.ashbyhq.com/posting-api/job-board/{token}`
- **SmartRecruiters** — public JSON feed: `https://api.smartrecruiters.com/v1/companies/{companyId}/postings`
- **Workday** — internal JSON API via `POST .../wday/cxs/{tenant}/{site}/jobs`; plain GET returns an empty JS shell (WebFetch can't issue POST, so this needs a fetch tool that supports it, or manual browser check)
- **iCIMS** — search results page, sometimes an XML feed. Some iCIMS sites are Jibe-powered (`app.jibecdn.com` assets) and expose a real JSON API at `{careers-domain}/api/jobs?page={n}` (10 per page, paginate via `page`, `totalCount` field is accurate) — try that before assuming it's a JS-only dead end like Cotiviti. The listed `?keywords=` query param is fuzzy/unreliable — better to pull all pages and filter titles client-side.
- **ADP (Workforce Now / myjobs)** — hosted recruiting page (`workforcenow.adp.com` or `myjobs.adp.com`). Workforce Now: public JSON API at `.../careercenter/public/events/staffing/v1/job-requisitions?cid={cid}&ccId={ccId}`. myjobs (Angular SPA): fetch `https://myjobs.adp.com/public/staffing/v1/career-site/{company}` for the `orgoid`, then `https://my.adp.com/myadp_prefix/mycareer/public/staffing/v1/job-requisitions` with header `orgoid: {orgoid}` (paginated via `$top`/`$skip`).
- **Lever** — public JSON feed: `https://api.lever.co/v0/postings/{company}?mode=json`. Canonical job URL: `https://jobs.lever.co/{company}/{id}`.
- **Breezy HR** — public JSON feed at `https://{company}.breezy.hr/json`, returning a **top-level JSON array** (not an object wrapper), one call, no pagination. Canonical job URL is the record's own `url` field, `https://{company}.breezy.hr/p/{12-hex-id}-{slug}`. A bad subdomain returns a clean **HTTP 404**, so the garbage control is unambiguous.
- **SAP SuccessFactors** — `careers.{company}.com/search/?q={keyword}` renders real job data server-side, no API needed — plain GET and parse `/job/{slug}/{id}/` links from the raw HTML. Note: the `q=` search is fuzzy/OR-matched across words (e.g. "data engineer" surfaces any "...Engineer..." title), so still filter titles client-side.
- **Rippling ATS** — Next.js app; job data isn't in the initial HTML, fetch `https://ats.rippling.com/_next/data/{buildId}/{companySlug}/jobs.json` (get current `buildId` from the `"buildId":"..."` field in the raw HTML of the jobs page — it changes on each Rippling deploy). Job list is under a react-query cache entry with `"items":[...]` containing `id`/`name`/`url`/`department`/`locations`.
- **UltiPro / UKG Pro Recruiting** — `recruiting.ultipro.com/{companyCode}/JobBoard/{boardGuid}/`. Job data isn't SSR'd (it's a Knockout.js app) — POST `https://recruiting.ultipro.com/{companyCode}/JobBoard/{boardGuid}/JobBoardView/LoadSearchResults` with body `{"opportunitySearch":{"Top":25,"Skip":0,"QueryString":"{keyword}"}}`, results in `.opportunities[]` (`Title`, `RequisitionNumber`, `Id`, `Locations[].LocalizedName`, `PostedDate`). Canonical URL: `https://recruiting.ultipro.com/{companyCode}/JobBoard/{boardGuid}/OpportunityDetail?opportunityId={Id}`.
- **Custom** — bespoke site; scraped as HTML, most likely to break or block bots. Several "blocked" custom sites turned out to have server-side-rendered JSON embedded in the raw HTML (Phenom People sites) or a directly-queryable underlying API (Oracle Recruiting Cloud, Workday CXS) — worth reverse-engineering via curl before giving up.

> 📐 **Structural rule (repaired 2026-08-24, amended 2026-09-04).** There is **exactly ONE roster
> table**, immediately below, holding all **97** rows under a single header. It had once drifted into
> **four** separate runs, and because only the first carried a header the other 45 companies did not
> render as table rows at all — worse, they physically sat under *"Removed from automated scanning"*,
> which asserted the opposite of the truth about them.
> - **When adding a company, append a row to the single table below** — never start a new run after a `##` heading.
> - **"Removed from automated scanning" must contain prose only, never table rows.** A row stranded under that heading is a live hazard: it reads as "don't scan this" for a company that is in fact scanned every run.
> - Cheap check for any scan that edits this file: the roster must be **97 contiguous `|` rows** directly under the header, and the removed section must contain no `|` at all.
> - 🔴 **THE CELL-COUNT CHECK MUST COUNT *UNESCAPED* PIPES — `(?<!\\)\|`, NOT `count("|")`** *(corrected 2026-09-02 r2; the count is now **3 cells**, not 4)*. Roster rows legitimately carry regex alternations inside backticks in the ATS column (`analy(t\|s)?ic`). Those are **correctly escaped and do not split the cell**, but a naive count reports them as violations: on 2026-09-02 r2 it flagged **8 rows, all 8 false**. **A check that cries wolf on eight healthy rows is a check nobody will read the ninth time.**
>   - ⚠️ **It did catch a real one the same run**, which is why it is worth fixing rather than dropping: an update script pasted a marketing string containing **unescaped** pipes and genuinely broke that row. **Escape any pipe in prose you add, or use `❘` (U+2758).**
>   - 🔴🔴 **THE SAME `(?<!\\)\|` RULE GOVERNS SPLITTING, NOT ONLY COUNTING — AND THE SPLITTING HALF IS THE ONE THAT HAS CAUSED DAMAGE** *(homed here 2026-09-07; the incident was 2026-09-04 r1)*. **An updater that splits a roster row on a bare `|` splits inside the escaped alternations too**, invents a cell boundary mid-regex, and rejoining with space padding breaks the escape into `\ | ` — leaving 5 content cells in a 3-column table. It corrupted **eight rows** that way: Humana, United Health, Hinge Health, Hilton, Pfizer, Quest Diagnostics, Home Depot, Marsh, several of them the highest-traffic boards. **RULE: split roster rows on `(?<!\\)\|` — unescaped pipes ONLY — and never pad a cell you did not author.** 🔴 Write the pattern to a file with `Write` and execute it; **never inline — this harness mangles backslashes.** This defect has now recurred at least three times, each time from a naive pipe split, which is why the rule lives here rather than in a script comment.
>   - 🔴 **Anchor the removed-section half on the `## Removed from automated scanning` HEADING, not a `find()` of similar prose.** The intro carries the phrase "Removed from the roster: Apple", so a loose search matches *before* the roster table and reports all 97 roster rows as violations of the prose-only rule.
>     - 🔴🔴 **AND THIS BULLET IS ITSELF THE TRAP — IT QUOTES THE HEADING VERBATIM, SO `text.index('## Removed from automated scanning')` MATCHES *HERE*, ABOVE THE ROSTER** *(hit live 2026-09-11 r2, which reported **396** unescaped pipes against a true 0)*. Writing the anchor as a literal string is the obvious implementation and it lands on the rule instead of on the section. ✅ **Match a LINE-START heading — `re.search(r'^## Removed from automated scanning', text, re.M)`** — and note the real lesson: **a rule that names its own anchor text becomes a false match for any checker that searches for that text.** The cure is to anchor on *structure* (line start, heading level), which is what the standing lesson two bullets down already says and what this bullet's own wording quietly defeated.
> - 🔵 **Standing lesson: a verification script that can produce a FALSE MISS will eventually produce a FALSE PASS.** Match case-insensitively, count escapes correctly, and anchor on structure rather than on prose that happens to be nearby.
